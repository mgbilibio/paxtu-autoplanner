Opção B escolhida   Versão inicial: 2026-06

Decisão do usuário (resposta "B"):
Criar versão web independente (Next.js + Supabase) em vez de evoluir o PaxtuAP Electron atual.
Prioridade #1: Controle de material/equipamento em acampamentos e reuniões.
Nome oficial: Sempre Alerta - Gestão
Local: paxtu-gestao/ (ao lado de PaxtuAP/)

1. Contexto e Objetivo

O Paxtu AutoPlanner já atende muito bem a progressão pessoal (blocos POR 2025+, especialidades, planejamento de reuniões, calendário). O grupo agora precisa de uma ferramenta operacional real para o dia a dia da gestão escoteira:

  • Controle de patrimônio e estoque de equipamentos
  • Empréstimos e logística de acampamentos/reuniões
  • Caixa / tesouraria (fase 2)
  • Compras e fornecedores (fase 3)

O sistema deve ser acessível por celular e computador por 4-8 escotistas/diretoria/tesoureiro, com dados em nuvem (Supabase) e fácil de usar por voluntários.

2. Escopo do MVP (Fase 1)

Foco exclusivo: Patrimônio + Logística de Material (a dor mais relatada).

Funcionalidades incluídas no MVP

  • Cadastro e catálogo de itens de estoque/patrimônio (com foto opcional, categoria, quantidade, estado, localização)
  • Categorias padrão escoteiras (Barracas, Dormir, Cozinha, Primeiros Socorros, Jogos, Uniformes, Outros)
  • Empréstimo de itens para eventos ou patrulhas (check-out / check-in)
  • Vinculação direta com eventos do calendário (ou cadastro simples de eventos dentro do sistema)
  • Checklist de material por evento/acampamento (o que cada patrulha deve levar)
  • Histórico completo de movimentações (quem pegou, quando, para qual evento, devolução)
  • Alertas de quantidade baixa e itens em manutenção
  • Relatórios simples: "O que está emprestado agora", "Material por evento", "Itens que precisam reposição"

Fora do escopo do MVP (fases futuras)

  • Caixa e controle de mensalidades
  • Compras e fluxo de aprovação
  • Integração automática com o PaxtuAP (import de membros/seções)
  • Multi-grupo (para já, um grupo por instância)

4. Permissões e Papéis

Reaproveitar os papéis já existentes no Paxtu:

  • ADMINISTRADOR / Diretoria — acesso total, pode excluir, ver relatórios financeiros (futuro)
  • Chefe de Seção / Assistente — cadastrar itens, registrar empréstimos, ver checklists
  • Leitura/Auditoria — só visualização e relatórios

5. Arquitetura Técnica

Stack escolhido:
• Next.js 15 (App Router, TypeScript, Server Actions)
• Tailwind CSS (continuidade visual com PaxtuAP)
• Supabase (Postgres + Auth + Storage + Realtime)
• shadcn/ui ou componentes próprios leves (para manter simplicidade)
• Deploy: Vercel (gratuito para hobby/non-profit)

Estratégia de integração com PaxtuAP (futuro)

  • Fase 1: sistemas independentes (membros cadastrados manualmente ou via import JSON simples)
  • Fase 2: exportar/importar membros e eventos do PaxtuAP via JSON ou arquivo
  • Fase 3 (opcional): PaxtuAP vira cliente "pesado" que consome a mesma API/Supabase para dados operacionais

7. Riscos e Mitigações

  • Risco: Escotistas não adotarem mais um sistema → Mitigação: MVP extremamente simples (3 telas principais), mobile-first, sem curva de aprendizado.
  • Risco: Perda de dados na nuvem → Mitigação: Supabase tem backups automáticos. Adicionar export JSON completo mensal.
  • Risco: Custo da nuvem → Mitigação: Supabase tier gratuito é mais que suficiente para 1 grupo com poucos milhares de registros.
